# 큐리 심사 체크 v1.2.0

출원번호별로 한 항목씩 확인하고 근거를 남기는 심사관용 자기점검 앱입니다. GitHub Pages와 내려받은 폴더에서 같은 HTML·CSS·JavaScript·WebP로 실행됩니다. 앱 사용에 설치, 계정, API 키, 외부 라이브러리가 필요하지 않습니다.

## 시작하기

1. [큐리 심사 체크](https://eqai-moip.github.io/Checklist/)를 엽니다. 공개 원본은 이 저장소의 `main` 루트입니다.
2. 출원번호를 입력하고 **점검 시작**을 누릅니다. 심사관 이름은 입력하지 않습니다.
3. 의견제출통지·최후통지·거절결정·등록결정 중 지금 확인할 문서를 선택합니다.
4. 질문과 확인 방법을 읽고, 직접 확인한 결과와 근거를 기록합니다.
5. **보완·최종확인**에서 남은 항목을 마치고 **전체 백업**으로 JSON 파일을 보관합니다.

처음이라면 **연습용 심사건으로 둘러보기**를 사용하세요. 같은 출원번호를 다시 입력하면 기존 기록을 엽니다. 이 앱은 문서 내용을 자동 판독하거나 AI 서비스에 전송하지 않습니다.

## 입력 내용은 어디에 저장되나요?

**이 앱은 출원번호, 체크 결과, 근거·메모를 서버로 전송하지 않습니다.** 현재 기기의 브라우저 저장 공간에 보관합니다. 운영자가 사용자의 점검 내용을 모으는 API·데이터베이스·분석 기능은 없습니다.

| 구분 | 동작 |
|---|---|
| 점검 기록 | 현재 브라우저의 `localStorage`에 자동 저장 |
| 다른 사용자·기기 | 자동 공유·동기화 기능 없음 |
| 백업 불러오기 | 파일을 브라우저 내부에서 검사·복원. 서버 업로드 없음 |
| JSON·CSV 내보내기 | 브라우저 다운로드 위치에 파일 저장. 저장 완료는 사용자가 확인 |
| GitHub Pages 접속 | 화면·코드·이미지 파일을 서버에서 다운로드. GitHub의 보안용 접속 IP 기록은 별도 |

브라우저 저장소와 백업 JSON은 앱에서 암호화하지 않습니다. 같은 브라우저 프로필을 사용하는 사람은 기록을 볼 수 있습니다. 사이트 데이터 삭제, 시크릿 창 종료, 저장 공간 부족 등에 대비하여 개인 업무 프로필과 업무용 백업 위치를 사용하세요. 브라우저 확장 프로그램·운영체제·동기화 폴더는 이 앱이 통제하지 않습니다.

브라우저 저장소의 경계는 **출처(프로토콜·호스트·포트)**입니다. `eqai-moip.github.io` 아래의 다른 프로젝트도 같은 출처이므로 기술적으로 저장소가 격리되지 않습니다. 운영자는 같은 출처에 게시하는 코드를 신뢰할 수 있게 관리해야 하며, 별도 격리가 필요하면 전용 도메인·서브도메인을 사용해야 합니다. 화면의 **내 기록·저장 안내**에서도 이를 설명합니다.

## v1.2.0 변경

- 본문 기본 크기를 약 17px, 주요 질문을 20~22px로 확대하고 작은 설명·상태·버튼의 시인성을 개선했습니다.
- 첫 화면에 세 단계 사용 순서와 연습 진입을 추가했습니다.
- 입력 기록의 저장·전송 범위를 상시 안내하고 상세 저장 안내 화면을 추가했습니다.
- Web Locks 지원 환경에서는 한 탭만 편집하며, 다른 탭은 읽기·백업을 허용합니다. 편집 탭을 닫은 뒤 **이 탭에서 편집 다시 시작**으로 이어갑니다.
- 브라우저 저장소 삭제, 수정 중인 추가 정보와 외부 저장의 충돌, 확인 대기 중 편집권 변경을 처리합니다.
- 출원번호를 브라우저 제목에 넣지 않습니다. 페이지 주소에는 내부 식별자만 해시로 사용하며 입력 내용을 요청 경로나 쿼리에 넣지 않습니다.
- 기존 CSP의 통신·폼 전송 제한을 유지하고 `no-referrer` 정책을 추가했습니다.
- 공개 경로·통신·저장·모바일 화면·오프라인 실행을 확인하는 개발용 검증을 추가했습니다.

Web Locks가 없는 브라우저에서는 버전·원문 재확인으로 충돌을 감지하지만 완전한 동시 쓰기 잠금은 제공하지 않습니다. 한 창에서 작업하세요. 업데이트 전의 오래된 앱 탭도 닫은 뒤 사용하세요.

## 폴더 실행과 기존 기록 이전

인터넷 없는 환경에서는 전체 저장소 또는 배포 ZIP을 내려받아 압축을 모두 풀고 `index.html`을 여세요. `js`, `css`, `assets`의 상대 위치를 유지해야 합니다. 웹사이트의 첫 로딩과 새로고침에는 인터넷이 필요합니다.

`file://` 앱의 기록은 웹사이트에 자동으로 옮겨지지 않습니다. 기존 앱에서 **전체 백업 → JSON 파일 저장**, 새 사이트에서 **백업·설정 → 백업 파일 불러오기** 순서로 이전하세요. 새 PC·브라우저·프로필·도메인으로 이동할 때도 같습니다. v1 백업 형식과 저장소 키는 유지했습니다.


Node.js와 Playwright는 개발 검증에만 사용됩니다. 사이트 방문자가 설치하거나 내려받는 실행 의존성이 아닙니다. GitHub Actions의 **Checklist verification**은 합성 자료로 실제 Chromium의 `file://`와 `/Checklist/` 실행을 검사하며, 공개 배포는 저장소의 Pages 설정을 따릅니다.

기준·질문·코드는 내장 원문을 바탕으로 만든 업무 보조 자료입니다. 최신 기관 지침과 대상 문서를 직접 확인해야 하며, 앱의 점검 완료가 공식 결재나 법적 결론 확정을 뜻하지 않습니다.
