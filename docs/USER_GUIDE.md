# 큐리 심사 체크 v1.1.0 사용 설명서

## 1. 실행과 첫 점검

이 앱은 출원번호별로 심사관이 직접 기준을 확인하고 근거를 기록하는 자기점검 도구입니다. 인터넷 연결이나 로그인 없이 로컬 폴더의 `index.html`을 열어 사용합니다.

1. ZIP 파일을 **모두 압축 풀기**로 풉니다.
2. 풀린 폴더에서 **index.html**을 두 번 클릭합니다.
3. 브라우저가 지정되지 않으면 Chrome 또는 Edge로 열기를 선택합니다.
4. 첫 화면에 **출원번호만** 입력하고 **점검 시작**을 누릅니다. Enter로도 시작할 수 있습니다.
5. **어떤 문서를 점검할까요?** 화면에서 의견제출통지·최후통지·거절결정·등록결정 중 하나를 선택합니다.
6. 현재 질문과 **이렇게 확인해요**를 읽고 원문을 대조한 뒤 결과와 필요한 기록을 남깁니다.
7. **기록하고 다음**으로 진행하고, 마지막에 **보완·최종확인**을 마칩니다.

이름·소속을 입력하는 과정은 없습니다. 출원번호만으로 이번 문서 종류를 알 수 없으므로 문서 종류는 직접 선택합니다. 이미 있는 출원번호를 입력하면 새 건을 만들지 않고 기존 점검을 엽니다.

별도 프로그램 설치, Node.js, npm, 로컬 서버, API 키가 필요하지 않습니다. 앱과 규칙 원문, WebP 캐릭터 이미지가 폴더 안에 포함되어 있습니다. `index.html`, `js/`, `css/`, `assets/`의 위치 관계를 유지하세요.

Chrome 또는 Edge의 최신 버전을 기본 사용 대상으로 설계했습니다. 이번 개선 작업에서는 실행 환경의 제한으로 실제 브라우저 실행과 `file://` 화면 확인이 차단되었습니다. JavaScript 핵심 로직·스프라이트 제어·모의 DOM의 앱 흐름과 정적 자원 구성을 검사했습니다. 모의 DOM 검사는 화면 렌더링이나 브라우저의 실제 파일 처리 검사가 아닙니다. 실제 `file://` 통합 실행, 반응형 배치, 다운로드·인쇄 및 Windows 업무 PC 검증은 수행하지 못했습니다. 처음 사용하는 PC에서는 연습용 심사건으로 저장, 새로고침, 백업 파일 다운로드와 복원을 확인하세요. 검사 범위는 `VALIDATION.md`에 기록합니다.

### 연습용 심사건

처음 화면 또는 **사용 안내**에서 **연습용 심사건으로 익히기**를 선택할 수 있습니다. `10-2026-0000000` 번호와 `[연습용]` 명칭으로 표시되는 가상 기록입니다. 실제 출원 조회나 실제 심사 결과가 아닙니다. 연습 기록도 일반 심사건처럼 자동 저장되므로 사용 후 보관함으로 옮기거나 삭제할 수 있습니다.

## 2. 출원번호와 필요한 추가 정보

| 입력값 | 사용 방법 |
|---|---|
| 출원번호 | 특허 `10` 또는 실용신안 `20`으로 시작하는 13자리입니다. 공백·하이픈을 정리해 `10-2026-0000001` 형태로 보관합니다. |
| 점검할 문서 | 출원번호를 입력한 다음 의견제출통지, 최후통지, 거절결정, 등록결정 중 선택합니다. 적용할 항목이 달라집니다. |
| 발명의 명칭 | 목록에서 심사건을 구별하고 검색하는 데 사용합니다. |
| 점검 예정일 | 심사건의 점검 계획일입니다. 공식 법정 기한 계산 기능은 아닙니다. |
| 마지막 청구항 번호 | 개별 점검할 청구항의 가장 큰 번호입니다. 0~200을 입력합니다. |

발명의 명칭·점검 예정일·마지막 청구항 번호는 모두 선택 사항이며 심사건 화면의 **추가 정보**에서 입력합니다. 기존 백업의 심사관 이름·기본 이름은 보존하지만 입력·검색·CSV·인쇄에는 사용하지 않습니다.

같은 출원번호를 다시 입력하면 기존 심사건을 엽니다. 같은 사건의 다음 단계로 진행할 때는 상단 문서 종류의 **변경** 또는 **추가 정보**에서 점검 유형을 바꾸고 종합 메모에 문서 버전과 점검 범위를 남깁니다. 단계별 판본을 독립적으로 남기려면 변경 전에 개별 JSON 백업 또는 보고서를 저장하세요.

점검 유형을 바꾸면 새 유형에 적용되는 항목을 표시합니다. 이전 유형에서 작성한 답변은 데이터에 남아 있으며 다시 해당 유형으로 돌아가면 확인할 수 있습니다. 완료된 사건을 수정할 때는 먼저 **점검 재개**를 선택해야 합니다.

### 삭제된 청구항이나 빠진 번호

유효한 청구항이 1, 2, 5항이면 마지막 청구항 번호에 `5`를 입력합니다. 청구항 3과 4는 **해당없음**으로 표시하고 삭제된 문서의 일자나 판본을 사유에 남깁니다. 번호를 줄여 화면에서 숨긴 기록은 보존되며 번호를 다시 늘리면 나타납니다.

`0`을 입력하면 청구항별 점검표를 만들지 않습니다. 이 설정에서도 관점별 점검은 가능합니다. 청구항별 확인이 필요한 사건에서는 번호를 입력하세요. 개별 청구항표를 사용하지 않는 사유가 있으면 종합 메모에 남기는 것을 권장합니다.

## 3. 8개 관점과 내장 기준

전체 기준은 **8개 관점, 66개 항목**입니다. 한 사건에 전체 66개가 동시에 표시되는 구조는 아니며, 선택한 점검 유형에 맞춰 적용 항목을 표시합니다.

| 관점 | 전체 항목 수 | 주된 확인 내용 |
|---|---:|---|
| 자료와 점검 범위 | 7 | 사건 동일성, 문서 연혁, 청구범위 판본, 원문 준비 |
| 절차의 효율성 | 8 | 절차 선택, 기회 부여, 보정 전후 경과, 최후통지 조건 |
| 명세서 해석의 정확성 | 14 | 구성·용어·기재 요건, 선행기재, 인용관계, 청구항 해석 |
| 검색의 적절성 | 8 | 검색 범위, 인용문헌 원문, 식별자·도면·수치의 대조 |
| 의견제출통지서 기재 적정성 | 9 | 이유와 대상항, 논리, 인용 위치, 통지의 설명 |
| 거절결정서 기재 적정성 | 6 | 이전 통지와 비교, 의견·보정 반영, 새 이유·조합 점검 |
| 등록청구항 최종 점검 | 7 | 최종 유효 청구항, 기재 명확성, 인용관계, 보호범위 |
| 출원인 관점과 마무리 | 7 | 설명 가능성, 증거와 예외 조건, 남은 확인, 최종 정리 |

| 점검 유형 | 적용 항목 수 |
|---|---:|
| 의견제출통지 | 51 |
| 최후통지 | 52 |
| 거절결정 | 59 |
| 등록결정 | 59 |

각 카드의 **이렇게 확인해요**에 확인 방법이 바로 표시됩니다. **진단기준·관련 코드·원문 보기**를 펼치면 연결된 규칙 원문과 진단코드를 읽을 수 있습니다. 코드 버튼은 해당 진단코드의 설명을 엽니다. **기준·규칙 사전**에서는 전체 항목, 84개 진단코드, 원문·출처를 검색합니다. 원문 읽기에도 인터넷이 필요하지 않습니다.

체크 질문은 EQAI_sheet와 AI_Reviewer의 보존 자료를 자기점검용으로 재구성한 내용입니다. EQAI_sheet 저장소의 공식 상세 매뉴얼 전체는 확보되지 않았습니다. 84개 코드 사전은 저장소에 보존된 첫 문장과 적용 안내를 담았습니다. 관련 코드의 표시는 참고 후보 연결이며 답변에 따라 코드를 자동 부여하는 기능이 아닙니다.

앱 화면 버전은 **v1.1.0**, 내장 기준 버전은 **1.0.0**입니다. 이번 화면 개선에서는 66개 질문, 적용 유형, 필수 기록 조건을 변경하지 않았습니다. 기준 확보일은 **2026-11-23**입니다. 오프라인 사용 중 규칙이 자동 갱신되지는 않습니다. 적용시점이 중요한 업무 판단은 해당 시점의 공식 원문과 대조해 기록하세요. 출처와 보존 범위는 `RULES_AND_SOURCES.md`에 상세히 적었습니다.

## 4. 한 항목씩 확인하고 기록하기

기본 화면은 **한 항목씩 보기**입니다. 현재 관점, 전체 항목 중 순서, 지금 확인할 질문, 확인 방법을 함께 표시합니다. 관점의 숫자 버튼으로 특정 질문에 바로 갈 수 있습니다. 큐리의 안내문과 움직임은 현재 관점과 선택한 결과·필수 기록 상태에 맞춰 바뀝니다.

각 항목에는 네 가지 상태가 있습니다. 처음에는 **미확인**이며, 확인완료·보완필요·해당없음 중 하나를 선택합니다. 선택한 뒤에는 **미확인으로 되돌리기**도 사용할 수 있습니다.

| 결과 | 의미 | 기록할 내용 |
|---|---|---|
| 미확인 | 아직 확인하지 않았거나 판단할 자료가 부족합니다. | 필요한 원문을 확보하고 확인한 뒤 결과를 변경합니다. |
| 확인완료 | 해당 질문을 대상 원문과 대조했습니다. | 확인한 문서·쪽·청구항과 필요한 메모를 남깁니다. |
| 보완필요 | 수정, 자료 확보 또는 추가 확인이 필요합니다. | 발견 내용, 근거, 보완 조치·처리 결과와 보완 완료 표시를 남깁니다. |
| 해당없음 | 이 사건에 규칙의 적용 대상이 없습니다. | 적용하지 않는 구체적 사유를 남깁니다. |

자료를 아직 읽지 않았거나 원문이 없다는 사정은 해당없음 사유와 다릅니다. 그런 경우에는 미확인 또는 보완필요로 남겨 다시 점검하세요.

### 다음 항목으로 이동하기

1. 질문과 확인 방법을 읽고 대상 원문을 직접 살펴봅니다.
2. 결과를 선택하면 해당 결과에 필요한 근거·메모 입력란이 나타납니다.
3. **이 항목을 마치려면**에 부족한 기록을 모두 표시합니다. 각 안내를 누르면 해당 입력란으로 이동합니다.
4. 필수 기록을 채운 뒤 **기록하고 다음**을 누릅니다. 결과를 선택하는 것만으로 다음 항목에 자동 이동하지 않습니다.

**이전**으로 앞 항목을 다시 볼 수 있습니다. 현재 항목을 지금 마치기 어렵다면 **나중에 확인**을 선택합니다. 이 동작은 이미 입력한 결과·근거·메모를 유지한 채 다음 항목으로 이동합니다. 미확인을 확인완료로 바꾸거나 누락을 지우지 않으며, 미완료 항목은 **보완·최종확인**에 남습니다.

**관점 전체 보기**를 선택하면 해당 관점의 모든 카드를 볼 수 있습니다. **미확인**, **보완필요**, **기록 미완료** 필터로 범위를 좁힐 수 있으며 **한 항목씩 보기** 또는 **이 항목에 집중하기**로 돌아옵니다. 관점 전체 보기에서도 같은 완료 조건을 적용합니다.

### 근거를 적는 예

“명세서 확인”처럼 넓게 쓰기보다 **문서 종류·일자·쪽 또는 문단·관련 청구항·실제 확인 결과**를 적으면 다음 검토에서 추적하기 쉽습니다.

> 2026-11-20자 보정서 3쪽, 청구항 5. 인용하는 청구항 1의 구성 A와 선행기재를 대조함.

인용문헌을 확인했다면 통지서에 적힌 위치와 인용문헌 원문의 실제 위치를 함께 기록합니다. PDF·HWPX 원문 파일 자체는 앱에 첨부하거나 저장하지 않습니다. 업무용 문서 프로그램으로 원문을 보면서 근거 위치를 입력하세요.

### 필수 기록과 진행률

기본 설정에서는 **핵심 확인** 항목을 확인완료로 표시할 때 근거 입력이 필요합니다. 보완필요 항목에는 발견 메모·근거·보완 조치와 보완 완료 표시가 필요하며, 해당없음에는 사유가 필요합니다.

진행률은 결과 버튼을 누른 개수만 세지 않습니다. 해당 항목의 필수 기록까지 충족한 경우에 진행률에 반영합니다. 목록의 전체 진행률에는 설정한 청구항별 표의 완료 기록도 포함됩니다. 이 비율은 업무의 자기점검 진행률이며 공식 품질 점수나 등급이 아닙니다.

상단의 **남은 항목**과 **보완·최종확인**에서는 누락이 있는 항목을 모아 볼 수 있습니다. **남은 항목 이어서 확인** 또는 목록의 **이동**을 누르면 해당 질문으로 돌아갑니다. 한 항목에 여러 누락 사유가 있으면 사유를 모두 보여 주며, 남은 항목 수에서는 한 항목으로 셉니다.

## 5. 청구항별 점검과 최종 완료

**청구항별 확인**에서는 번호를 눌러 각 청구항의 구성, 인용관계, 선행기재와 근거를 기록합니다. 관점별 상세 점검에 더해 개별 청구항을 빠뜨리지 않았는지 확인하는 표입니다. 모든 번호에 결과를 기록하고, 해당없음에는 사유를 남깁니다. 보완필요에는 **발견 내용·확인 근거·처리 결과·보완 완료 표시**가 모두 필요합니다. 청구항별 확인완료 상태에서는 근거 입력을 필수로 요구하지 않지만 추적 가능한 근거를 적는 것이 좋습니다.

보완항목 수에는 관점별 점검과 청구항별 점검의 기록을 모두 포함합니다. 같은 쟁점이 두 표에 기록되어 있다면 각각 세므로 고유한 법적 하자의 개수와 같지는 않습니다.

진행 단계는 **문서 선택 → 항목 점검 → 보완·최종확인 → 점검 완료**로 표시됩니다. 관점별 마지막 항목 다음에는 설정된 청구항별 기록으로 이어지고, 청구항별 기록이 없거나 마지막 청구항까지 진행하면 최종확인으로 이동합니다.

1. **보완·최종확인**을 엽니다.
2. 미확인, 핵심항목 근거 누락, 해당없음 사유 누락, 미처리 보완사항을 확인합니다.
3. 각 항목의 **이동**으로 돌아가 필요한 기록을 채웁니다.
4. 모든 필수 기록이 채워지면 대상 문서와 최종 청구범위를 직접 확인했다는 체크를 선택합니다.
5. **이번 점검 완료하기**를 누릅니다.

완료 후에는 기록을 잠가 실수로 변경되는 것을 줄입니다. 다시 수정하려면 **점검 재개**를 누릅니다. 이전 완료·재개 등의 주요 이력은 남습니다. 완료 이후 근거 필수 설정이 바뀌어 필수 기록이 부족해지면 **재확인 필요**로 표시될 수 있습니다.

완료 표시는 심사관의 자기점검 기록입니다. 기관의 공식 결재, 법적 결론 확정, 특허성 또는 무하자 보증을 의미하지 않습니다.

## 6. 내 심사건 관리

**내 심사건**에서 출원번호·발명의 명칭으로 검색하거나 진행 상태·점검 유형으로 목록을 줄일 수 있습니다. 최근에 기록한 사건이 위에 표시됩니다.

심사건의 **더 보기**에서 개별 JSON 백업, 체크 결과 CSV, 보관함 이동을 사용할 수 있습니다. 보관함으로 이동하면 관리 중인 기본 목록에서 빠지고 기록이 잠깁니다. 보관함 필터로 찾아 **보관 해제**하면 다시 관리할 수 있습니다.

삭제는 보관함에 있는 심사건에서 선택합니다. 삭제 전 개별 JSON 백업 다운로드를 시작하므로 브라우저의 다운로드 목록에서 파일이 실제로 저장되었는지 확인하세요. 내려받은 백업 파일은 앱이 자동으로 삭제하지 않습니다.

**종합 메모·이력**에는 문서 목록과 판본, 검토 범위, 핵심 쟁점과 후속조치를 적습니다. 주요 이력은 등록, 상태 변경, 완료·재개, 보관과 같은 사건을 기록합니다. 모든 글자 수정의 이전 내용을 복원하는 버전 관리 기능은 아닙니다.

## 7. 자동 저장과 백업·복원

### 자동 저장이 이루어지는 위치

입력한 기록은 **현재 브라우저의 로컬 저장 공간**에 자동 저장됩니다. 상단의 저장 상태를 확인하세요. 일반 입력은 잠시 기다렸다 저장되고, 주요 동작에서는 즉시 저장을 시도합니다.

HTML 폴더에 데이터 파일을 자동으로 쓰거나 ZIP 안에 기록을 추가하지 않습니다. 파일 경로, 브라우저, 프로필이 바뀌거나 브라우저 저장 데이터를 정리하면 기록이 보이지 않을 수 있습니다. 시크릿·임시 모드나 기관 정책에서는 자동 저장이 제한될 수 있습니다. 자동 저장만을 장기 보관 방법으로 삼지 말고 JSON 백업을 보관하세요.

자동 저장소에 접근할 수 없는 환경에서는 **파일 백업 모드**로 작업할 수 있습니다. 현재 화면에서 편집하거나 JSON을 불러올 수 있지만 기록이 브라우저에 자동 보존되지는 않습니다. 새로고침하거나 창을 닫기 전에 현재 작업 JSON을 저장하고, 다음 작업 때 그 JSON을 다시 불러오세요.

### 마지막 점검 위치 기억하기

같은 브라우저에서는 출원별 마지막 항목·화면과 한 항목씩 보기/관점 전체 보기 선택을 별도로 기억합니다. 새로고침하거나 심사건을 다시 열면 유효한 위치로 돌아옵니다. 유형 변경으로 이전 항목이 적용되지 않게 되었거나 저장된 위치가 없으면 현재 남은 항목을 기준으로 엽니다. 완료·보관된 심사건은 최종확인 화면에서 시작합니다.

이 화면 위치는 `quri.examiner.cursor.v1`이라는 별도 브라우저 저장 값이며 **JSON 백업에는 포함되지 않습니다**. 새 브라우저로 옮기면 질문의 기록은 복원되지만 마지막 화면 위치가 그대로 이동하지는 않습니다. 문서 종류를 아직 고르지 않은 새 심사건은 주요 이력에도 선택 대기 상태를 기록하므로, 위치 정보 없이 JSON만 복원해도 문서 선택부터 다시 안내합니다. 위치 저장에 실패하더라도 점검 기록의 백업·복원 형식은 바뀌지 않습니다.

### 내보내기 종류

| 형식 | 포함 내용 | 다시 불러와 작업 계속하기 |
|---|---|---|
| 전체 JSON 백업 | 전체 심사건, 관점·청구항 결과, 근거, 메모, 이력, 설정 | 가능 |
| 개별 JSON 백업 | 선택한 심사건과 설정 | 가능. 전체 교체 선택 시 다른 사건이 제외되는 점에 유의 |
| 심사건 목록 CSV | 전체 심사건의 목록과 진행 현황 | 불가 |
| 개별 체크 결과 CSV | 현재 유형의 관점·청구항별 결과와 기록 | 불가 |
| 보고서 | 현재 심사건의 사람이 읽기 좋은 인쇄 화면 | 불가. 브라우저에서 인쇄 또는 PDF 저장 |

v1.0.0의 JSON 백업과 같은 버전 1 형식을 사용합니다. 이전 백업에 있던 이름 정보는 JSON에 보존하며, 새 화면에서 추가 정보를 수정해도 지우지 않습니다. CSV와 인쇄 보고서에는 심사관 이름을 표시하지 않습니다.

JSON 백업과 CSV에는 문서 원본이 포함되지 않습니다. 내려받기는 브라우저의 저장 위치 설정을 따릅니다. 앱이 파일의 실제 디스크 저장 완료나 사용자가 고른 폴더를 확인할 수는 없으므로 다운로드 목록을 확인하세요. 내보낸 파일은 일반 텍스트 또는 인쇄물이며 암호화 기능은 없습니다.

### 새 PC로 옮기는 순서

1. 기존 PC에서 **전체 백업** JSON을 저장합니다.
2. 앱 폴더 전체와 백업 JSON을 새 PC로 옮깁니다.
3. 새 PC에서 `index.html`을 엽니다.
4. **백업·설정 → 백업 파일 선택**을 누르거나 JSON 파일 한 개를 끌어 놓습니다.
5. 미리 표시되는 출원 수와 중복 수를 확인하고 가져오기 방식을 선택합니다.

**새 출원만 병합**은 현재 기록을 유지하고 없는 출원번호만 추가합니다. 같은 출원번호의 더 최신 답변을 자동으로 합치는 방식이 아닙니다. 기존 설정도 유지합니다.

**전체 교체**는 별도 확인 후 현재 작업 전체를 가져온 백업 상태로 바꿉니다. 교체 전에 현재 작업의 백업 다운로드를 시작합니다. 개별 심사건 파일로 전체 교체하면 현재 목록의 다른 사건도 제외되므로 전체 작업 복원이 맞는지 확인하세요.

백업 파일은 32 MiB 이하를 받습니다. 앱 식별자·버전·출원번호·데이터 필드를 검사한 뒤 사용하며, 형식이 손상되었거나 지원하지 않는 버전은 오류를 알립니다.

### 같은 앱을 여러 창에서 열었을 때

한 브라우저 창에서 작업하는 방식을 권장합니다. 다른 창의 저장 버전이 감지되면 변경 중인 창은 자동 저장을 멈추고 알립니다. 각 창의 현재 작업을 JSON으로 보관한 뒤 **저장된 데이터 다시 불러오기**로 기준 기록을 확인하세요. 복원 병합은 같은 출원번호의 답변을 자동 병합하지 않습니다.

브라우저 저장소에는 여러 창을 한 번에 잠그는 데이터베이스 트랜잭션이 없으므로, 동시에 같은 순간 저장하는 모든 상황을 완벽하게 방지하는 기능은 아닙니다.

## 8. 문제 해결과 편의 설정

| 상황 | 확인할 사항 |
|---|---|
| 준비 화면에서 멈춤 | ZIP을 모두 풀었는지, `js/`·`css/`·`assets/`가 함께 있는지 확인합니다. JavaScript가 허용되어야 합니다. |
| 큐리 그림이 보이지 않음 | `assets/` 폴더와 WebP 파일이 빠지지 않았는지 확인합니다. |
| 다음으로 갈 수 없음 | 현재 카드의 **이 항목을 마치려면**에 표시된 기록을 채웁니다. 지금 확인하기 어려우면 **나중에 확인**으로 남깁니다. |
| 완료할 수 없음 | 보완·최종확인의 목록과 직접 확인 체크를 확인합니다. 상태만 선택하고 근거·사유가 빠진 경우도 목록에 나옵니다. |
| 자동 저장 공간 부족 | 현재 작업을 JSON으로 먼저 저장한 뒤, 보관된 백업을 확인하고 브라우저 공간을 정리합니다. |
| 저장 접근 거부 | 파일 백업 모드에서 편집·불러오기를 계속할 수 있습니다. 새로고침·종료 전에 현재 작업 JSON을 저장합니다. 브라우저 정책과 임시 모드 여부도 확인합니다. |
| 기존 저장 내용 손상 | 앱은 읽지 못한 원문을 자동으로 덮어쓰지 않습니다. 기존 저장 원문을 내려받고 정상 JSON 백업으로 전체 교체합니다. |
| 폴더 이동 후 목록이 비어 있음 | 이전 위치·프로필의 저장 영역과 달라졌을 수 있습니다. 별도로 보관한 JSON을 가져옵니다. |
| 문서를 넣을 곳을 찾을 수 없음 | 이 버전은 직접 점검하는 앱이며 PDF·HWPX 판독이나 문서 첨부 기능은 제공하지 않습니다. |

**백업·설정**에서 핵심 확인 항목의 근거 필수 설정과 큐리 애니메이션 멈추기를 바꿀 수 있습니다. 점검 화면의 큐리 안내 옆 **멈춤/재생** 버튼으로도 움직임을 조절합니다. 운영체제의 동작 줄이기 설정이 켜져 있으면 앱의 재생 설정과 관계없이 정지 화면을 유지합니다. 숨겨진 탭이나 화면 밖의 캐릭터도 재생을 멈춥니다.

큐리는 기존 WebP에 실제로 있는 인사·가리키기·읽기·완료의 네 동작을 사용합니다. 문서 확인과 청구항 대조에서는 읽기, 근거 기록과 보완 정리에서는 안내, 필수 기록을 마쳤을 때는 완료 동작을 연결합니다. 서로 다른 안내 상황에 같은 실제 동작을 사용할 수 있으며 새 그림을 생성하거나 원문을 자동 분석하는 기능은 아닙니다.

근거 필수 설정을 해제하면 핵심항목의 확인완료에 근거를 필수로 요구하지 않습니다. 보완필요·해당없음의 필수 기록은 유지됩니다. 꼼꼼한 검토 이력을 남기려면 기본 설정을 유지하는 것을 권장합니다.

이 앱에는 LLM 호출, KIPRIS 조회, 로그인, 원격 데이터 동기화, 공식 결재 기능이 없습니다. 점검 기준과 다음 할 일을 안내하는 큐리의 애니메이션은 인터넷 없이 재생되며, 화면의 상태와 사용자가 작성한 근거가 기록의 기준입니다.
