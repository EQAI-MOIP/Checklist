# 검증 기록 — 큐리 심사 체크 v1.0.0

작성일: 2026-11-23

## 결과의 범위

Node.js 기본 모듈만 사용하는 자동검증 **29개가 통과**했습니다. JavaScript 구문, 내장 규칙의 참조 연결, 정적 자원 경로, 외부 실행 의존성, WebP 원본 크기·해시도 확인했습니다.

**실제 브라우저 통합 검증은 수행하지 못했습니다.** 제작 환경에서 Chromium 시작은 소켓 권한 제한으로 중단되었고, 브라우저 도구의 `file://` 열기도 보안 정책에 의해 차단되었습니다. 권한 확대 요청 역시 자동 승인 정책에서 거절되었습니다. 이를 우회하지 않았습니다. 실제 브라우저 화면, 다운로드·인쇄 대화상자, Windows 운영 PC에서의 동작을 검증했다고 주장하지 않습니다.

## 실행한 자동검증

개발 환경에서 다음 명령을 실행합니다. 앱 사용자에게 Node.js 설치가 필요한 것은 아닙니다.

```sh
node --test tests/*.test.cjs
```

## 내장 규칙과 파일

- 전체: 8개 관점, 66개 체크항목, 84개 진단코드, 38개 원문 참조.
- 의견제출통지: 51항목, 최후통지: 52항목, 거절결정: 59항목, 등록결정: 59항목.
- 84개 진단코드가 모두 하나 이상의 체크항목에 참조 후보로 연결됨.
- `1511`, `1521`, `1522`는 우수사례로 유지됨. 숫자 규칙으로 하자에 잘못 분류하지 않음.
- HTML 실행 자원은 모두 같은 패키지 안에 존재함.
- 외부 CDN, 원격 웹폰트, 서버, 런타임 패키지, module import, 데이터 fetch 없음.
- 실행 코드에 `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon` 호출 없음.
- CSP에 `connect-src 'none'` 지정.
- WebP 3개는 원본 바이트·투명도·크기를 확인함. 해시는 `assets/README.txt` 및 `SHA256SUMS.txt` 참조.
- 정적 검사에서 외부 요청 경로가 없음을 확인했으며, 실제 브라우저의 네트워크 요청을 측정한 결과는 아님.

## 코드 검토에서 수정한 사항

1. 저장소 접근 불가와 손상 데이터를 구분해, 자동 저장이 막혀도 JSON을 화면에 불러와 편집할 수 있도록 파일 백업 모드를 제공함.
2. 백업 파일을 구성하지 못하면 심사건 삭제를 중단함.
3. 다른 창에서 현재 심사건을 삭제·교체한 경우 대시보드로 돌아가도록 처리함.
4. 편집 대화상자를 연 뒤 심사건이 완료·보관된 경우 저장 직전 잠금 상태를 재확인함.
5. 이미 선택한 보완필요 버튼을 다시 눌러도 기존 보완 완료 표시를 지우지 않음.
6. 청구항별 보완필요에도 근거를 요구하고, 보완 집계에 청구항별 기록을 포함함.

## 적용 PC에서 처음 사용할 때

ZIP을 모두 푼 후 `index.html`을 Chrome 또는 Edge에서 열고, 가상 연습용 심사건으로 다음을 확인하면 됩니다.

1. 큐리 이미지·움직임과 관점별 점검표가 표시되는지 확인합니다.
2. 점검 결과·근거를 입력하고 새로고침했을 때 남는지 확인합니다.
3. JSON 전체 백업을 내려받고, 다른 폴더나 브라우저에서 불러옵니다.
4. 핵심 근거·해당없음 사유·미처리 보완이 남으면 최종확인에서 안내하는지 확인합니다.
5. 보고서의 인쇄 화면과 PDF로 저장을 확인합니다.

자동 저장이 차단된 환경에서는 새로고침 전에 파일을 저장해야 합니다. 앱이 파일 백업 모드라고 안내하면 브라우저 저장을 전제로 작업하지 마세요.

## 현재 한계

- `localStorage` 정책과 용량은 브라우저·보안 설정·파일 위치에 따라 달라집니다.
- 여러 창의 비교·쓰기는 원자적인 잠금이 아닙니다. 한 창에서 작업하는 방식을 권장합니다.
- 다운로드 API는 저장 요청을 시작하며 실제 디스크 저장 완료를 앱이 확인하지는 못합니다.
- JSON·CSV는 암호화되지 않습니다. 업무 환경의 보관 기준에 맞게 다룹니다.
- 원문 PDF·HWPX를 첨부·보관·자동 판독하거나 AI로 판단하는 기능은 없습니다.
- 점검 질문은 확보한 저장소 원문을 재구성한 자기 점검 안내이며, 최신 법령이나 기관의 공식 상세 매뉴얼 전체를 대체하지 않습니다.

이 한계는 기능 구현과 별도로 표시한 검증 범위이며, 통과한 자동검증을 실제 운영 환경의 검증으로 확대하지 않습니다.
