## 검증 범위의 구분

모의 DOM 시험은 실제 앱 코드와 이벤트를 실행하지만 화면을 렌더링하지 않습니다. 브라우저 시험은 합성 자료만 사용하며, 개인정보·실제 출원 자료를 업로드하지 않습니다. 정적 통신 API 검사는 코드 변경 실수를 감지하는 장치이며 임의의 악성 코드 전체에 대한 증명은 아닙니다.

서버에 입력 기록을 전송하지 않는 구조와 별개로 호스팅 접속 기록, 같은 출처의 다른 앱, 비암호화 로컬 데이터, 브라우저 확장·운영체제는 [입력 내용 저장·전송 검토](PRIVACY_REVIEW.md)에 명시했습니다.

## 이번 흐름의 주요 검증

1. 출원번호 하나로 생성하며, 연속 제출이나 하이픈 유무가 다른 같은 번호가 중복 건을 만들지 않습니다.
2. 문서 종류를 선택하기 전 새로고침해도 선택 화면이 유지됩니다. 재개 위치를 포함하지 않는 JSON 백업에서도 `awaiting-type` 이력으로 미선택 상태를 복원합니다.
3. 핵심 근거가 빠졌으면 ‘기록하고 다음’이 이동하지 않고 해당 입력으로 초점을 옮깁니다.
4. 해당없음 사유와 보완필요의 발견 내용·근거·처리 결과·보완 완료 표시를 각각 안내합니다.
5. ‘나중에 확인’은 현재 답변을 변경하지 않습니다. 해당 항목은 최종 미완료 목록에 남습니다.
6. 관점 전체 보기에서 다른 항목을 수정하면 큐리 안내와 한 항목 보기의 재개 위치도 함께 바뀝니다.
7. 마지막 관점에서 설정된 청구항별 확인으로 이어지고, 최종 확인 체크 후에만 완료·잠금 처리됩니다.
8. 기존 v1 백업의 숨겨진 이름 필드, 현재 유형에서 제외된 응답, 줄어든 청구항 번호의 기록을 보존합니다.
9. 완료·보관된 심사건의 편집을 막습니다. 저장 접근 거부·할당량 오류를 성공으로 표시하지 않습니다.
10. 자동 저장이 불가능해도 현재 작업의 JSON 백업 내용을 만들 수 있습니다. 실제 디스크 다운로드 완료까지 검증한 것은 아닙니다.
11. 본문 바로가기가 출원 경로를 바꾸지 않으며, 항목·청구항 표시와 접근성 문구가 필수 기록 충족 여부를 반영합니다.
12. 애니메이션 정지가 항목 이동 후에도 유지되고, 같은 화면에서 다시 켤 수 있습니다.

## 실제 브라우저에서 실행할 별도 시험

`tests/browser-flow.test.cjs`에 실제 `file://`와 네트워크 차단을 사용하는 선택적 시험을 준비했습니다. 개발 환경에 Playwright와 Chromium/Chrome이 이미 설치되어 있고 브라우저 실행이 허용될 때 다음 명령으로 실행할 수 있습니다. 시험 자체는 패키지를 내려받지 않습니다.

```sh
QURI_BROWSER_TEST=1 node --test tests/browser-flow.test.cjs
```

Windows PowerShell에서는 다음과 같이 실행합니다.

```powershell
$env:QURI_BROWSER_TEST = '1'
node --test tests/browser-flow.test.cjs
```

필요하면 `QURI_CHROMIUM`에 설치된 브라우저 경로를 지정합니다. `QURI_SCREENSHOT_DIR`를 지정하면 화면을 저장할 수 있습니다. Playwright는 개발 시험용이며 앱의 실행 파일에서는 로드하지 않습니다. 명시적으로 시험을 켠 상태에서 브라우저 시작이 실패하면 실패로 보고합니다.

병합 검토 시 확인할 실제 화면 시나리오:

- 인터넷을 끈 상태에서 압축을 모두 풀고 `index.html`을 열어 번호 입력·문서 선택·큐리 표시를 확인합니다.
- 결과 선택→근거→다음, 나중에 확인→재개, 남은 항목→보완→최종 완료를 진행합니다.
- 1440/1024/390px 화면, 키보드 이동과 확대 상태에서 질문·버튼·필수 기록이 잘 보이는지 확인합니다.
- 같은 폴더에서 새로고침 후 기록이 유지되는지, 전체 JSON 백업·복원과 보고서 인쇄가 동작하는지 확인합니다.

## 저장 방식의 한계

브라우저의 로컬 저장 정책과 용량은 PC·프로필·파일 위치에 따라 달라집니다. 작업 후 JSON을 별도로 보관해야 합니다. 화면의 재개 위치는 브라우저 편의 정보이며 JSON 백업에 포함되지 않습니다. 복원한 기록은 유효한 위치 또는 첫 미완료 항목에서 열립니다.

다운로드 API는 파일 저장 요청을 시작하며 실제 디스크 저장 완료를 앱이 확인하지는 못합니다. 여러 창의 비교·쓰기는 원자적 잠금이 아니므로 한 창에서 작업하는 것이 좋습니다. PDF·HWPX 자동 판독이나 LLM 진단은 이 앱의 기능에 포함되지 않습니다.
