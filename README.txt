큐리 심사 체크 v1.2.0
출원번호별로 근거를 남기는 웹·오프라인 자기점검 앱

v1.2.0 웹사이트 이용 안내

GitHub Pages에서는 사이트 주소를 열어 바로 시작할 수 있습니다.
출원번호와 체크·근거·메모는 현재 기기의 브라우저 저장 공간에 보관하며,
이 앱은 입력 내용을 서버·GitHub·AI 서비스로 전송하지 않습니다.
서버는 화면 파일을 제공하고 GitHub는 보안용 접속 IP를 기록할 수 있습니다.

첫 화면과 메뉴의 "내 기록·저장 안내"에서 저장 범위를 확인하세요.
브라우저의 사이트 데이터 삭제·시크릿 창 종료·PC/프로필 변경에 대비해
전체 JSON 백업을 보관하고 다운로드 완료를 확인하세요.
앱은 브라우저 저장 내용과 JSON 파일을 암호화하지 않습니다.
같은 github.io 호스트의 다른 프로젝트는 브라우저 저장 공간이 기술적으로
격리되지 않습니다. 필요하면 운영자가 전용 도메인/서브도메인을 사용하세요.

지원되는 브라우저에서는 한 탭만 편집합니다. 두 번째 탭은 읽기·백업용이며,
편집 탭을 닫은 뒤 "이 탭에서 편집 다시 시작"으로 이어갈 수 있습니다.
오래된 버전의 탭은 닫고, 잠금 미지원 환경에서는 한 창에서 작업하세요.

웹사이트를 처음 열거나 새로고침할 때는 인터넷이 필요합니다.
아래의 폴더 실행 방식은 그대로 사용할 수 있습니다. 기존 폴더 기록을
웹사이트로 옮길 때는 기존 앱의 JSON 백업을 새 사이트에서 불러오세요.
기록은 앱 폴더나 PC 사이로 자동 이동하지 않습니다.

최신 상세 안내: README.md, docs/GITHUB_PAGES.md, docs/PRIVACY_REVIEW.md
검증 범위와 실행 결과: docs/VALIDATION.md

폴더에서 바로 시작하기

1. ZIP 파일을 마우스 오른쪽 버튼으로 눌러 "압축 풀기" 또는 "모두 압축 풀기"를 실행합니다.
2. 압축이 풀린 앱 폴더를 엽니다.
3. index.html을 두 번 클릭하여 브라우저에서 엽니다.
4. 첫 화면에 출원번호만 입력하고 "점검 시작"을 누르거나 Enter를 누릅니다.
5. 지금 점검할 문서를 의견제출통지·최후통지·거절결정·등록결정 중에서 고릅니다.
6. 한 화면의 질문과 확인 방법을 읽고 원문을 대조한 뒤 결과·근거·메모를 기록합니다.
7. "기록하고 다음"으로 이어 갑니다. 지금 마치기 어려운 항목은 "나중에 확인"으로 남깁니다.
8. "보완·최종확인"에서 남은 항목을 마치고 직접 확인 체크 후 점검을 완료합니다.
9. 상단의 "전체 백업"을 눌러 JSON 파일을 별도로 보관합니다.

심사관 이름을 입력할 필요가 없습니다. 같은 출원번호를 다시 입력하면 기존 기록을 엽니다.
출원번호만으로 문서 종류를 판단할 수 없으므로 시작 직후 문서 종류는 직접 선택합니다.
발명의 명칭·예정일·청구항 번호 등은 필요할 때 "추가 정보"에서 입력할 수 있습니다.

ZIP 내부 미리보기 상태에서 index.html만 열면 이미지나 JavaScript가 누락될 수 있습니다.
index.html과 js, css, assets 폴더의 상대적 위치를 유지해 주세요.
프로그램 설치, Node.js, npm, 실행 서버, API 키, 인터넷 연결이 필요하지 않습니다.
Chrome 또는 Edge의 최신 버전을 기본 사용 대상으로 설계했습니다.
실제 브라우저 검증의 실행 환경과 결과는 docs/VALIDATION.md를 확인해 주세요.
처음 사용할 PC에서 연습용 심사건의 저장·새로고침·백업·복원을 확인해 주세요.

무엇을 할 수 있나요?

- 출원번호 하나로 시작하며 심사관 이름·소속 입력 없이 개인의 점검 기록을 관리합니다.
- 현재 관점, 전체 항목 순서, 지금 확인할 질문과 확인 방법을 함께 표시합니다.
- 한 항목씩 점검하는 화면을 기본으로 사용하고, 필요하면 "관점 전체 보기"로 전환합니다.
- 출원번호별로 점검 결과, 확인 근거, 관련 청구항, 메모와 보완 조치를 기록합니다.
- 의견제출통지·최후통지·거절결정·등록결정의 네 가지 점검 유형을 선택합니다.
- 전체 8개 관점, 66개 체크 항목 중 선택한 유형의 적용 항목을 표시합니다.
- 청구항 번호별로 점검 결과와 보완사항을 따로 남깁니다.
- 현재 항목의 필수 기록 누락을 모두 보여 주며, 안내를 누르면 해당 입력란으로 이동합니다.
- "기록하고 다음"은 현재 항목의 필수 기록을 확인합니다. "나중에 확인"은 기존 기록을 유지하며 이동합니다.
- 미확인, 근거 누락, 해당없음 사유 누락, 미처리 보완사항을 최종확인에 모아 보여 줍니다.
- 84개 진단코드와 통지서·결정서·등록청구항 규칙 원문을 오프라인으로 읽습니다.
- 기존 16프레임 WebP의 실제 인사·안내·읽기·완료 동작을 현재 항목과 입력 상태에 연결합니다.
- 큐리 옆 "멈춤/재생" 버튼과 운영체제의 동작 줄이기 설정으로 움직임을 조절합니다.
- 같은 브라우저에서는 마지막 항목과 보기 방식을 기억해 이어서 점검합니다.
- 심사건 검색, 상태·유형별 보기, 점검 재개, 보관함, 주요 변경 이력을 제공합니다.
- 전체 또는 개별 심사건의 JSON 백업, CSV 출력, 인쇄 보고서를 제공합니다.

저장 위치 — 반드시 확인해 주세요

자동 저장 위치는 현재 브라우저의 로컬 저장 공간입니다.
HTML 폴더나 ZIP 안에 점검 데이터 파일이 자동 생성되는 방식이 아닙니다.
브라우저·프로필·파일 경로가 바뀌거나 브라우저 데이터를 지우면 기록이 보이지 않을 수 있습니다.
앱 폴더만 다른 PC로 옮겨도 기존 브라우저 기록이 따라가지는 않습니다.
작업을 마칠 때, 폴더를 이동할 때, PC나 브라우저를 바꿀 때는 전체 백업 JSON을 저장하세요.
자동 저장 실패가 표시되면 현재 작업 백업을 먼저 내려받아 보관하세요.
자동 저장을 사용할 수 없는 환경에서는 "파일 백업 모드"로 편집·불러오기가 가능합니다.
이 모드의 기록은 현재 열린 화면에 있으므로 새로고침하거나 창을 닫기 전에 JSON을 저장하세요.
마지막 화면 위치는 점검 데이터와 별도로 이 브라우저에 저장되며 JSON 백업에 포함되지 않습니다.
새 브라우저에서 복원하면 남은 항목을 기준으로 시작합니다. 문서 종류를 아직 선택하지 않은
새 심사건은 백업 복원 후에도 문서 선택 화면부터 안내합니다.
JSON과 CSV는 암호화되지 않은 일반 파일입니다. 업무 자료 보관 기준에 맞는 위치에 보관하세요.

백업을 복원하는 방법

"백업·설정" → "백업 파일 선택"에서 이 앱으로 만든 JSON을 선택합니다.
"새 출원만 병합"은 기존 출원번호의 기록을 유지하고 새로운 번호만 추가합니다.
"전체 교체"는 확인을 거쳐 현재 작업 전체를 가져온 백업으로 바꿉니다.
개별 심사건 JSON으로 전체 교체하면 다른 심사건도 현재 목록에서 제외되므로 내용을 확인하세요.
CSV와 인쇄 보고서는 열람용이며 복원에는 JSON 백업을 사용합니다.
v1.0.0의 JSON 백업을 계속 사용할 수 있습니다. 이전에 저장한 심사관 이름과 기본 이름은
백업 데이터에 보존하지만, v1.1.0의 입력·검색·CSV·인쇄 화면에는 표시하지 않습니다.

청구항 번호 입력

"추가 정보"의 "마지막 청구항 번호"에 최종 검토 대상의 가장 큰 청구항 번호를 입력합니다.
예를 들어 1, 2, 5항이 유효하면 5를 입력하고 3, 4항에는 해당없음 사유를 남깁니다.
0은 청구항별 표를 만들지 않는 설정입니다. 청구항별 표는 최대 200번까지 지원합니다.
번호를 줄여 숨겨진 이전 기록도 데이터에 보존되며 다시 늘리면 표시됩니다.
청구항별 보완필요에도 발견 내용, 확인 근거, 처리 결과와 보완 완료 표시가 필요합니다.

기준의 의미

EQAI_sheet의 관점 구조와 AI_Reviewer의 진단규칙·진단코드를 참고했습니다.
앱의 화면 버전은 v1.1.0이고, 내장 기준 버전은 1.0.0을 유지합니다.
이번 개선은 66개 질문, 적용 유형과 필수 기록 조건을 바꾸지 않습니다.
원문 확보일은 2026-11-23이며, 기준이 인터넷으로 자동 갱신되지는 않습니다.
EQAI_sheet 저장소의 상세 매뉴얼은 별도 업로드 전 안내 상태였습니다.
따라서 체크 질문은 확인한 규칙 원문을 자기점검용으로 재구성한 내용입니다.
84개 코드 사전은 저장소에 수록된 첫 문장과 적용 안내를 보존한 자료입니다.
점검 완료와 진행률은 자기점검 기록이며 공식 품질 점수, 기관 결재 또는 법적 결론이 아닙니다.

이 앱은 심사관이 직접 점검하는 앱입니다.
LLM·KIPRIS 등 외부 API를 호출하지 않으며 PDF·HWPX를 자동 판독하지 않습니다.
문서는 업무용 프로그램으로 열어 확인하고 파일명·일자·쪽·청구항을 근거에 적습니다.
API 키, 실제 업무 문서, 사용자 데이터는 배포 ZIP에 포함하지 않았습니다.

자세한 안내

- docs/USER_GUIDE.md: 사용 방법, 완료 조건, 백업·복원과 문제 해결
- docs/RULES_AND_SOURCES.md: 항목 구성, 적용 범위, 기준 원문과 고정 커밋
- docs/ARCHITECTURE.md: 코드 구성, 저장 형식, 오프라인 설계와 수정 방법
- assets/README.txt: WebP 원본 출처, 해상도, 해시와 애니메이션 사용 정보
- references/: 참조한 규칙 원문 사본
- docs/VALIDATION.md: 실제로 수행한 검사와 미확인 범위

개발용 tests/의 Node 검사와 선택적 Playwright 브라우저 검사는 앱 실행에 필요하지 않습니다.
배포 앱에는 Playwright 또는 다른 외부 실행 라이브러리를 포함하지 않습니다.

문서를 읽는 Markdown 프로그램이 없어도 앱 왼쪽 "사용 안내"와
"기준·규칙 사전"에서 주요 내용과 원문을 읽을 수 있습니다.
