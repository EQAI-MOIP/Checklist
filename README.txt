큐리 심사 체크 v1.0.0
출원번호별로 근거를 남기는 오프라인 자기점검 앱

바로 시작하기

1. ZIP 파일을 마우스 오른쪽 버튼으로 눌러 "압축 풀기" 또는 "모두 압축 풀기"를 실행합니다.
2. 압축이 풀린 QURI_Examiner_Checklist_v1.0.0 폴더를 엽니다.
3. index.html을 두 번 클릭하여 브라우저에서 엽니다.
4. "새 심사건"을 누르고 출원번호, 점검 유형, 필요한 기본정보를 입력합니다.
5. 관점별로 원문을 확인하면서 결과·근거·메모를 기록합니다.
6. "보완·최종확인"에서 남은 기록을 확인하고 이번 점검을 완료합니다.
7. 상단의 "전체 백업"을 눌러 JSON 파일을 별도로 보관합니다.

ZIP 내부 미리보기 상태에서 index.html만 열면 이미지나 JavaScript가 누락될 수 있습니다.
index.html과 js, css, assets 폴더의 상대적 위치를 유지해 주세요.
프로그램 설치, Node.js, npm, 실행 서버, API 키, 인터넷 연결이 필요하지 않습니다.
Chrome 또는 Edge의 최신 버전을 기본 사용 대상으로 설계했습니다.
제작 환경의 보안 정책으로 실제 브라우저 실행이 차단되었습니다.
따라서 JavaScript 핵심 로직·스프라이트 검증과 정적 파일 검사를 수행했으며,
실제 브라우저의 file:// 통합 실행과 Windows 운영 PC 검증은 수행하지 못했습니다.
처음 사용할 PC에서 연습용 심사건의 저장·새로고침·백업·복원을 확인해 주세요.

무엇을 할 수 있나요?

- 출원번호별로 점검 결과, 확인 근거, 관련 청구항, 메모와 보완 조치를 기록합니다.
- 의견제출통지·최후통지·거절결정·등록결정의 네 가지 점검 유형을 선택합니다.
- 전체 8개 관점, 66개 체크 항목 중 선택한 유형의 적용 항목을 표시합니다.
- 청구항 번호별로 점검 결과와 보완사항을 따로 남깁니다.
- 미확인, 근거 누락, 해당없음 사유 누락, 미처리 보완사항으로 바로 이동합니다.
- 84개 진단코드와 통지서·결정서·등록청구항 규칙 원문을 오프라인으로 읽습니다.
- 실제 16프레임 WebP로 움직이는 큐리가 현재 단계와 다음 할 일을 안내합니다.
- 심사건 검색, 상태·유형별 보기, 점검 재개, 보관함, 주요 변경 이력을 제공합니다.
- 전체 또는 개별 심사건의 JSON 백업, CSV 출력, 인쇄 보고서를 제공합니다.

저장 위치 — 반드시 확인해 주세요

자동 저장 위치는 현재 브라우저의 로컬 저장 공간입니다.
HTML 폴더나 ZIP 안에 점검 데이터 파일이 자동 생성되는 방식이 아닙니다.
브라우저·프로필·파일 경로가 바뀌거나 브라우저 데이터를 지우면 기록이 보이지 않을 수 있습니다.
앱 폴더만 다른 PC로 옮겨도 기존 브라우저 기록이 따라가지는 않습니다.
작업을 마칠 때, 폴더를 이동할 때, PC나 브라우저를 바꿀 때는 전체 백업 JSON을 저장하세요.
자동 저장 실패가 표시되면 현재 작업 백업을 먼저 내려받아 보관하세요.
자동 저장을 사용할 수 없는 환경에서는 "파일 백업 모드"로 편집·불러오기가 가능합니다.
이 모드의 기록은 현재 열린 화면에 있으므로 새로고침하거나 창을 닫기 전에 JSON을 저장하세요.
JSON과 CSV는 암호화되지 않은 일반 파일입니다. 업무 자료 보관 기준에 맞는 위치에 보관하세요.

백업을 복원하는 방법

"백업·설정" → "백업 파일 선택"에서 이 앱으로 만든 JSON을 선택합니다.
"새 출원만 병합"은 기존 출원번호의 기록을 유지하고 새로운 번호만 추가합니다.
"전체 교체"는 확인을 거쳐 현재 작업 전체를 가져온 백업으로 바꿉니다.
개별 심사건 JSON으로 전체 교체하면 다른 심사건도 현재 목록에서 제외되므로 내용을 확인하세요.
CSV와 인쇄 보고서는 열람용이며 복원에는 JSON 백업을 사용합니다.

청구항 번호 입력

기본정보의 "마지막 청구항 번호"에 최종 검토 대상의 가장 큰 청구항 번호를 입력합니다.
예를 들어 1, 2, 5항이 유효하면 5를 입력하고 3, 4항에는 해당없음 사유를 남깁니다.
0은 청구항별 표를 만들지 않는 설정입니다. 청구항별 표는 최대 200번까지 지원합니다.
번호를 줄여 숨겨진 이전 기록도 데이터에 보존되며 다시 늘리면 표시됩니다.
청구항별 보완필요에도 발견 내용, 확인 근거, 처리 결과와 보완 완료 표시가 필요합니다.

기준의 의미

EQAI_sheet의 관점 구조와 AI_Reviewer의 진단규칙·진단코드를 참고했습니다.
원문 확보일은 2026-11-23이며, 기준이 인터넷으로 자동 갱신되지는 않습니다.
EQAI_sheet 저장소의 상세 매뉴얼은 별도 업로드 전 안내 상태였습니다.
따라서 체크 질문은 확인한 규칙 원문을 자기점검용으로 재구성한 내용입니다.
84개 코드 사전은 저장소에 수록된 첫 문장과 적용 안내를 보존한 자료입니다.
점검 완료와 진행률은 자기점검 기록이며 공식 품질 점수, 기관 결재 또는 법적 결론이 아닙니다.

이 앱은 심사관이 직접 점검하는 앱입니다.
LLM·KIPRIS 등 외부 API를 호출하지 않으며 PDF·HWPX를 자동 판독하지 않습니다.
문서는 업무용 프로그램으로 열어 확인하고 파일명·일자·쪽·청구항을 근거에 적습니다.
API 키, 실제 업무 문서, 사용자 데이터는 배포 ZIP에 포함하지 않았습니다.
